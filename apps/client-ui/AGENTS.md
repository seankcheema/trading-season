# Angular UI instructions

- Follow existing standalone components, reactive forms, OnPush change detection, and signal patterns.
- Import shared components through exported @shared/ui-components subpaths; avoid copying their implementations into this app.
- Preserve accessible labels, validation feedback, keyboard interactions, and responsive behavior.
- Check submission handlers before assuming API wiring exists. Integration changes must select the correct [authentication contract](../../docs/reference/api.md).
- `/api` is split across both Java services by path. Trading paths (`/api/orders`, `/api/instruments`) go to Order and Sell on 8081; everything else goes to Holdings and Trade on 8082. A new backend path needs the same entry in both [proxy.conf.json](proxy.conf.json) and [nginx.conf](nginx.conf).
- Validate UI changes with the app build and relevant Angular tests. Use --no-watch; see [development](../../docs/guides/development.md#checks).
- Keep unit tests under src and end-to-end tests under e2e, which Playwright owns and the unit-test builder excludes. When an auth or registration contract changes, update the [e2e stand-in](e2e/fixtures/api-stub.ts) with it.
- Do not edit files under this application while a dev server is running; the watcher rebuilds on every change, and a Playwright run against that server fails on the restart.
- Keep `/dashboard/markets/:symbol` aligned with the dashboard's centered `max-w-[1600px]` shell. At desktop widths it is a `100dvh` no-document-scroll trading view; its Overview, News, AI, and Recent Orders panels may scroll internally. Metrics, consensus, news, and AI commentary on that page remain explicitly demo data. Live symbol prices, OHLCV candles, range volume, and connection state must continue to come from the market APIs. Both the dashboard dialog and market ticket submit through [OrderService](src/app/dashboard/orders/order.service.ts). Reuse the shared account/time controls, simulation helpers, and activity-row component. Recent Orders shows the selected account's latest 20 orders across all stocks, filtered by the simulation cursor. Preserve actual audit timestamps and retry balance refreshes independently of order submission.
