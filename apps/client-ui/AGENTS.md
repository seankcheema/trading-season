# Angular UI instructions

- Follow existing standalone components, reactive forms, OnPush change detection, and signal patterns.
- Import shared components through exported @shared/ui-components subpaths; avoid copying their implementations into this app.
- Color from the theme tokens in [src/styles.css](src/styles.css), never a literal color or a fixed `white` or `black` utility, which looks right in one theme only. A color the tokens lack gets a token in both the light `:root` block and `:root.dark`; see [Themes](README.md#themes).
- Preserve accessible labels, validation feedback, keyboard interactions, and responsive behavior. The target is WCAG 2.2 AA; [Accessibility](README.md#accessibility) names the one place each convention lives. Do not add `outline-none` or a ring utility (focus is one global outline), do not bind `aria-describedby` on an `hlmInput` (use `appDescribedBy`), and give a new list-as-table, `role="menu"` or modal the roles, keys and focus handling already used.
- Content that is still loading shows a placeholder in its shape, not a zero, an empty state, or a line of "Loading" text; see [Loading states](README.md#loading-states). Use the `skeleton` class from [src/styles.css](src/styles.css), hide the blocks with `aria-hidden`, and name what is loading in a visually hidden `role="status"`. Keep the class identical to the Reporting UI's.
- Check submission handlers before assuming API wiring exists. Integration changes must follow the contract in the owning service README (for example [auth](../auth-service/README.md)).
- `/api` is split across both Java services by path. Trading paths (`/api/orders`, `/api/instruments`) go to Order and Sell on 8081; everything else goes to Holdings and Trade on 8082. A new backend path needs the same entry in both [proxy.conf.json](proxy.conf.json) and [nginx.conf](nginx.conf). The Auth Service is reached the same way on the relative `/auth` prefix (port 3001), so the app makes no cross-origin call and is deployable to S3 behind CloudFront; see [Static UIs on S3](../../infrastructure/README.md#static-uis-on-s3).
- Validate UI changes with the app build and relevant Angular tests. Use --no-watch; see the [README](README.md#commands).
- Keep unit tests under src and end-to-end tests under e2e, which Playwright owns and the unit-test builder excludes. When an auth or registration contract changes, update the [e2e stand-in](e2e/fixtures/api-stub.ts) with it.
- Do not edit files under this application while a dev server is running; the watcher rebuilds on every change, and a Playwright run against that server fails on the restart.
- Keep `/dashboard/markets/:symbol` aligned with the dashboard's centered `max-w-[1600px]` shell. At desktop widths it is a `100dvh` no-document-scroll trading view; its Recent Orders panel may scroll internally. Metrics on that page remain explicitly demo data. The header sits below the dialog backdrops (`z-50`), so a dialog covers it. Live symbol prices, OHLCV candles, range volume, and connection state must continue to come from the market APIs. Both the dashboard dialog and market ticket submit through [OrderService](src/app/dashboard/orders/order.service.ts). Reuse the shared account/time controls, simulation helpers, and activity-row component. Recent Orders shows the selected account's latest 20 orders across all stocks, filtered by the simulation cursor. Preserve actual audit timestamps and retry balance refreshes independently of order submission.
- Never put the selected account, or any other id of the user's data, in a URL: no route or query parameter, no `routerLink` or `navigate` that carries it. Pass it through [AccountStore](src/app/dashboard/accounts/account-store.service.ts); see [Selected account](README.md#selected-account).
