# API Contracts - AI Agent Guidance

Guidance for AI agents working with OpenAPI schemas and API contracts.

## Directory Purpose

**Single source of truth** for API definitions. Defines:
- OpenAPI 3.0 schema (main contract)
- Generated TypeScript interfaces
- Generated Java DTOs

**Tech Stack:**
- OpenAPI 3.0.0
- TypeScript code generators
- Java/Maven code generators

---

## When to Modify This Package

✅ **Modify here:**
- Add new API endpoints to `openapi.yaml`
- Update request/response schemas
- Fix API documentation
- Generate TypeScript/Java artifacts
- Add security definitions
- Define error models

❌ **Do NOT modify:**
- Frontend implementation (see `apps/business-logic-ui/`)
- Backend implementation (see `apps/business-backend/`)
- Shared UI components (see `packages/shared-ui-components/`)

## OpenAPI Schema Structure

### Basic Anatomy
```yaml
openapi: 3.0.0                    # Version
info:                             # API metadata
  title: API Name
  version: 1.0.0
servers:                          # Server URLs
  - url: http://localhost:8080
paths:                            # All endpoints
  /api/endpoint:
    get:                          # HTTP method
      operationId: getEndpoint
      responses:
        '200':
          description: Success
          content:
            application/json:
              schema:
                $ref: '#/components/schemas/Model'
components:
  schemas:                        # Reusable data models
    Model:
      type: object
      properties:
        id:
          type: integer
        name:
          type: string
```

## Common Tasks

### Add New Endpoint

```yaml
paths:
  /api/orders:
    post:
      summary: Create order
      operationId: createOrder
      tags:
        - orders
      requestBody:
        required: true
        content:
          application/json:
            schema:
              $ref: '#/components/schemas/CreateOrderRequest'
      responses:
        '201':
          description: Order created
          content:
            application/json:
              schema:
                $ref: '#/components/schemas/Order'
        '400':
          description: Bad request
          content:
            application/json:
              schema:
                $ref: '#/components/schemas/ErrorResponse'
        '401':
          description: Unauthorized
```

### Add Request/Response Schema

```yaml
components:
  schemas:
    CreateOrderRequest:
      type: object
      required: [symbol, quantity, price]
      properties:
        symbol:
          type: string
          description: Stock symbol (e.g., AAPL)
          example: AAPL
        quantity:
          type: number
          format: decimal
          description: Number of shares
          example: 100
        price:
          type: number
          format: decimal
          description: Price per share
          example: 150.50

    Order:
      type: object
      properties:
        id:
          type: integer
          format: int64
        symbol:
          type: string
        quantity:
          type: number
        price:
          type: number
        status:
          type: string
          enum: [pending, filled, cancelled]
        createdAt:
          type: string
          format: date-time
```

### Add Authentication

```yaml
components:
  securitySchemes:
    bearerAuth:
      type: http
      scheme: bearer
      bearerFormat: JWT
      description: JWT token authentication

security:
  - bearerAuth: []    # Apply to all endpoints
```

Or specific endpoints:
```yaml
paths:
  /api/protected:
    get:
      security:
        - bearerAuth: []    # This endpoint requires auth
```

### Define Common Error Response

```yaml
components:
  schemas:
    ErrorResponse:
      type: object
      required: [code, message]
      properties:
        code:
          type: integer
          description: HTTP status code
          example: 400
        message:
          type: string
          description: Error message
          example: Invalid email format
        details:
          type: array
          description: Detailed error info
          items:
            type: object
            properties:
              field:
                type: string
              issue:
                type: string
          example:
            - field: email
              issue: Must be a valid email
```

## Code Generation

### Generate TypeScript Interfaces
```bash
npm run generate:typescript
```

**Output:** `src/typescript/generated/models/*.ts`

```typescript
export interface CreateOrderRequest {
  symbol: string;
  quantity: number;
  price: number;
}

export interface Order {
  id: number;
  symbol: string;
  quantity: number;
  price: number;
  status: 'pending' | 'filled' | 'cancelled';
  createdAt: string;  // ISO 8601 date-time
}
```

### Generate Java DTOs
```bash
mvn generate-sources
```

**Output:** `src/java/generated/CreateOrderRequest.java`

```java
@Data
@Builder
public class CreateOrderRequest {
    @NotBlank
    private String symbol;
    
    @DecimalMin("0.01")
    private BigDecimal quantity;
    
    @DecimalMin("0.01")
    private BigDecimal price;
}
```

## Workflow

1. **Edit `openapi.yaml`** with new endpoints
2. **Validate:** `npm run validate`
3. **Generate artifacts:** `npm run generate`
4. **Commit:** `git add . && git commit -m "docs: Add new API endpoint"`
5. **Frontend uses:** `import { CreateOrderRequest } from '@packages/api-contracts'`
6. **Backend uses:** Same DTOs via Maven generation

---

## Key Rules

1. **Edit `openapi.yaml` only** — Don't modify generated files
2. **Never break existing schemas** — Only add or create new versions
3. **Document everything** — Use `description` fields
4. **Use examples** — Help frontend/backend understand expected values
5. **Follow naming conventions:**
   - Requests: `CreateUserRequest`, `UpdateOrderRequest`
   - Responses: `User`, `Order`, `ErrorResponse`
   - Schemas (nouns): PascalCase

## Path Parameters vs Query Parameters

### Path Parameters (in URL)
```yaml
paths:
  /api/orders/{id}:
    get:
      parameters:
        - name: id
          in: path           # ← path parameter
          required: true
          schema:
            type: integer
```

### Query Parameters (in URL)
```yaml
paths:
  /api/orders:
    get:
      parameters:
        - name: status
          in: query          # ← query parameter
          schema:
            type: string
            enum: [pending, filled, cancelled]
```

## Common Issues & Fixes

| Issue | Cause | Fix |
|-------|-------|-----|
| "Schema not found" | Reference typo `$ref: '#/...'` | Check schema name in `components/schemas/` |
| Generated types incomplete | Schema not defined | Add schema to `components/schemas/` |
| Backend can't deserialize | JSON property mismatch | Ensure schema property names match Java fields |
| Frontend type errors | Outdated generated code | Run `npm run generate:typescript` |
